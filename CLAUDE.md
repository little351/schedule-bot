# Расписание ГЦОЛИФК: Telegram-бот и мини-приложение

Правила проекта для Claude Code. Читаются автоматически в начале каждой сессии.

## Как работать с владельцем

- Владелец проекта Артём. Пишет по-русски, отвечать тоже по-русски: коротко, сначала вывод, без воды.
- Не спрашивать лишнего. Если есть разумный вариант по умолчанию, выбрать его и сказать, какой выбран.
- На рискованные идеи (удалить функцию, убрать команду, переделать то, чем пользуются) сначала дать своё мнение
  с плюсами и минусами, а не сразу делать. Пример: Артём хотел вырезать `/week`, хотя люди пользуются им чаще
  мини-аппа, и отговорили.
- Главное правило: ничего не сломать для пользователей. После каждой правки проверить, что всё остальное в боте и
  мини-аппе работает как раньше. Больше 1000 пользователей, большинство с первого курса.
- Ничего не удалять и не перезаписывать в данных на проде (Neon, Render).

## Как вносить изменения

- Каждая задача делается в отдельной ветке и уходит отдельным PR в `main`. Сливает Артём сам. После слияния Render
  сам выкладывает новую версию (auto-deploy), поэтому `main` всегда должна работать.
- Перед PR обязательно `python -m pytest -q`: должны пройти все тесты. Тот же прогон делает CI (`.github/workflows/tests.yml`).
- На каждое исправление ошибки добавлять тест, который ловит эту ошибку.
- Описание PR по-русски: «Было:» и «Стало:» понятным языком, потом коротко «Как».
- Не коммитить: `.env`, `schedule.db`, выгрузки пользователей и резервные копии, любые токены и пароли.
  Репозиторий публичный.

| `bot.py` | Бот (python-telegram-bot 22, вебхук): команды, выбор курс → направление → группа, команды владельца, автозадачи (`run_due_jobs`, `/health`) |
| `routes.py` | API мини-аппа `/api/...`: расписание, заметки, «Моя группа», игра «Блоки» и магазин скинов |
| `telegram_auth.py` | Проверка подписи `initData` из Telegram (без неё API не доверяет пользователю) |
| `database.py` | Хранилище: занятия в локальной SQLite, пользователи и состояние в Postgres (Neon), без `DATABASE_URL` всё в SQLite |
| `schedule_parsers/` | Разбор таблиц `.xlsx`/`.xls` по форматам; `parser.py` старый вход к ним |
| `lms_sync.py`, `lms_check.py` | Подгрузка файлов с сайта вуза lms.sportedu.ru (Moodle), диагностика доступа |
| `formatting.py` | Текст расписания для сообщений бота |
| `api.py` | Локальный сервер только для мини-аппа, без бота |
| `webapp/index.html` | Мини-приложение целиком (HTML, CSS, JS в одном файле) |
| `webapp/tetris.js` | Игра «Блоки» |
| `data/` | Файлы расписания по курсам (`1k`…`5k`), `programs.json`, `teachers.json`, `lms_sources.json`; правила в `data/README.md` |
| `scripts/teacher_contacts.py` | Сбор контактов преподавателей с сайта вуза (запускается из Actions) |
| `.github/workflows/` | `tests.yml` (тесты), `daily-jobs.yml` (раз в сутки будит бота), `teacher-contacts.yml` |

## Важные ограничения

- **Neon (Postgres).** Исходящий трафик бесплатного тарифа почти исчерпан, поэтому никаких лишних чтений из базы:
  не читать в цикле, не делать `SELECT` «на всякий случай», кешировать. Бесплатные базы Render не использовать.
- **`schedule_parsers/` не трогать без нужды.** Любая правка меняет `parsed_version`, и тогда бот заново скачивает
  из Neon все файлы подгрузки, около 24 МБ трафика.
- **Кеш разобранных таблиц** `data/.parsed-cache.json.gz`. После правки файлов в `data/`, парсеров или
  `data/programs.json` нужно пересобрать его командой `python parser.py --build-cache`, иначе упадёт `tests/test_schedule_cache.py`.
- **Секреты только в Render → Environment**, в код и чат их не писать: `BOT_TOKEN`, `DATABASE_URL`, `LMS_LOGIN`,
  `LMS_PASSWORD`, `WEBHOOK_SECRET`, `CRON_SECRET`. Список переменных в `.env.example`.
- **Автозадачи.** Бесплатный Render засыпает через 15 минут без запросов. Раз в сутки (07:00 МСК) GitHub Actions
  вызывает `POST /cron`, и бот делает еженедельную копию владельцу и подгрузку с сайта вуза. Состояние смотрится
  командой `/health`. Подгрузка не пишет пользователям в чат.
- **Загрузка файлов расписания и команды `/users`, `/stats`, `/backup`, `/broadcast`, `/sync`, `/lms_check`, `/health`**
  работают только у владельца (`OWNER_ID`).
- **«Блоки».** Слово «Тетрис» в интерфейсе не использовать: это торговая марка. После каждой правки `webapp/tetris.js`
  увеличить номер в `tetris.js?v=N` в `webapp/index.html`, иначе у людей останется старая версия из кеша Telegram.
- **Донаты.** Номер для перевода по СБП стоит под расписанием и во вкладке «Важное». Сбор Т-Банка не предлагать.
- **Не читаются парсерами:** листы для иностранцев, ПСС, «Иностранный язык», заочная форма (установочные сессии).

## Проверка у себя

```bash
python -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate
pip install -r requirements.txt pytest
python -m pytest -q                # все тесты, без интернета и без базы
```

Мини-приложение без бота: `uvicorn api:app --reload`, затем открыть http://localhost:8000. Сервер стартует
около 30 секунд, потому что разбирает таблицы; данные берутся из `data/`, база в локальном `schedule.db`.
В `api.py` нет токена бота, поэтому подпись Telegram не проверяется и пользователь берётся из `telegram_id`
в запросе. Это только для локальной проверки: на проде API верит лишь подписанному `initData`.

Бот целиком (`uvicorn main:app`) локально запускать только с **отдельным тестовым ботом** от @BotFather и без
`DATABASE_URL` от прода. При запуске `main.py` бот ставит вебхук на `PUBLIC_URL`, поэтому с боевым токеном он
перехватит всех пользователей с Render на ваш компьютер, а боевая база получит лишние запросы и записи.
Для вебхука нужен публичный адрес (например, ngrok), его надо указать в `PUBLIC_URL`. Сам бот `.env` не читает:
переменные нужно загрузить в окружение (macOS/Linux: `set -a; source .env; set +a`).
