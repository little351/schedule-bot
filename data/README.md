# Файлы расписания

Файлы лежат в папках по курсам: `1k/`, `2k/`, `3k/`, `4k/`, `5k/`. Бот ищет файлы
во всех подпапках `data/`, поэтому файл в «неправильной» папке тоже будет прочитан. `programs.json` лежит в корне `data/`.

Когда владелец отправляет файл боту, бот кладёт его в папку курса из имени (`..._1k_...`), а если курса в имени
нет, в папку по курсу из самой таблицы.

Все `.xlsx` и `.xls` из этой папки и её подпапок загружаются при старте бота. Направление, курс и группы бот берёт
из самих таблиц, имя файла на чтение не влияет; схема имён нужна, чтобы файлы было легко искать.

    <направление>_<курс>k_<группы>.xls(x)

- поля разделяются `_`: направление, курс, группы;
- несколько направлений или групп разделяются `+`, тире остаётся внутри названия группы;
- название группы латиницей строчными: `т2-08-26` → `t2-08-26`, `сг1-3-26` → `sg1-3-26`, «1 группа» → `gr1`;
- диапазон групп: `gr1-gr6`; подгруппы одного кода (`Т2-07-26/1`, `/2`) указываются общим кодом `t2-07-26`.

Примеры: `49.03.04_1k_gr1-gr6.xlsx`, `44.03.01_1k_sg2-1-26+sg2-2-26.xls`.

Если группа есть в двух файлах, действует файл, который идёт позже по алфавиту, поэтому при замене файла
старый нужно удалить, а не оставлять рядом под другим именем.

## Автоподгрузка с сайта вуза (lms.sportedu.ru)

Бот может сам раз в день (`LMS_SYNC_INTERVAL_HOURS`, по умолчанию 20 часов) заходить на сайт и забирать файлы расписания. Если какие-то уже опубликованные дни у группы поменялись, мини-апп показывает этой группе плашку «В расписании есть изменения» (14 дней), под расписанием строка «обновлено дд.мм». В чат ничего не отправляется.
Порядок источников: свежая подгрузка, затем файлы, загруженные владельцем, затем файлы из репозитория.
Если подгрузка выключена или сломалась, всё работает на запасных источниках.

Переменные окружения на Render (в код и репозиторий их записывать нельзя): `LMS_LOGIN`, `LMS_PASSWORD`.
Необязательные: `LMS_SYNC_ENABLED=0` (выключить), `LMS_TIMEOUT_SECONDS` (ответ одной страницы, по умолчанию 30),
`LMS_MAX_MINUTES` (общий срок одного запуска, по умолчанию 10).

Источники описаны в `lms_sources.json`:

    {
      "base_url": "https://lms.sportedu.ru",
      "min_ratio": 0.6,
      "pages": [{"label": "1 курс, 1 поток (гр.1-6)", "url": "/course/view.php?id=15179", "include": "расписан"}],
      "resources": []
    }

- `pages`: страницы курсов с файлами (список из документа «РАСПИСАНИЕ»). Бот открывает только их, по одной.
  Страница, которая не открылась, пропускается и попадает в отчёт. `include` / `exclude` (необязательно): названия
  файлов на странице, которые брать или не брать. Без `include` берутся все файлы-таблицы.
- `resources`: прямые ссылки на файлы.
- `"level": "m"` у страницы или ссылки: это магистратура. Из таких файлов берутся только направления с кодом
  вида `38.04.02`, остальные группы отбрасываются (чтобы «1 группа» без направления в шапке не подменила
  одноимённую группу бакалавриата). Уровень в боте и мини-аппе определяется по коду направления: `XX.04.XX`
  магистратура, остальное бакалавриат. Выбор «Бакалавриат / Магистратура» появляется, когда в расписании есть оба.
- Файл принимается, только если он читается парсером, в нём не пропали группы относительно прошлой версии
  и число занятий не упало ниже `min_ratio` от прежнего. Иначе остаётся прошлая версия.
- В базе хранится только последняя хорошая версия каждого файла; старый файл, чьи группы целиком вошли в новый, удаляется.

Команды владельца: `/sync list` (показать названия файлов на страницах, чтобы подобрать `include`), `/sync` (запустить
сейчас и посмотреть отчёт, в нём есть расход памяти), `/lms_check` (диагностика доступа к сайту). Плановые запуски
начинаются после первого ручного `/sync`.

## Преподаватели (data/teachers.json)

Список для карточки «Преподаватели» в мини-приложении, собран из файла «Кафедры и кадровый состав РУС «ГЦОЛИФК»» (по данным сайта gtsolifk.ru). Структура: `departments` — кафедры, у каждой `id`, `name`, необязательная `note` и `teachers`. У преподавателя `id`, `name`, `position`; можно добавить `about`, `phone`, `email` (показываются, если заполнены; неизвестное не пишется). `id` — ФИО латиницей, он не должен меняться: к нему будут привязаны отзывы. Если человек работает на двух кафедрах, у него один и тот же `id` в обеих. Чтобы добавить кафедру, допишите объект в `departments`.

## Кеш разобранных таблиц (data/.parsed-cache.json.gz)

Чтобы старт бота не разбирал все таблицы заново (около 10 секунд), готовые записи файлов из `data/` лежат в сжатом
кеше. Ключ кеша — содержимое файла, поэтому новый или изменённый файл (в том числе загруженный в бот) просто
разбирается, как раньше. После правки файлов в `data/`, парсеров или `data/programs.json` пересоберите кеш:
`python parser.py --build-cache`. Если забыть, тест `tests/test_schedule_cache.py` упадёт в CI. Neon при этом не
используется.
